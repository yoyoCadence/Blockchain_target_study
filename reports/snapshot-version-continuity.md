# 相鄰快照版本連續性

在獨立暫存副本重現：後一份快照以同 ID 改寫舊來源 publisher，重算 hash 並維持 parent 連結後，原 `readSnapshots` 仍接受。既有版本檢查會拒絕這項修改，但原本只用於準備快照及最新資料比對，沒有逐對核對保存歷史。

歷史讀取在確認 hash／工作區／parent／單一路徑後，對每一對相鄰快照重用既有 `assertVersionHistory`：舊輸入與來源必須原封保留；公式與論點規則不能刪除、退版或同版本改寫。合法追加的唯一 ID／新版本，以及明確升版的公式／規則仍可讀取。沒有新金融公式或門檻，也未改版本規則本身。

新增 20 項回歸覆蓋兩工作區的來源／輸入改寫與刪除、同版本定義變更、定義刪除與退版、合法追加／升版、API 400 且檔案不變，以及真實金融／論點／全部歷史 hash。API 探針即使目前資料與最新快照一致，仍會因更早的來源被改寫而拒絕。與既存血緣測試合計 26 項通過；全套結果見[驗證紀錄](validation.md)。

原二份合成、六份正式快照及所有 sources／inputs／spec 保留。這是內部版本連續性驗證，不是外部不可變儲存、簽章認證、全文來源查證或全部 snapshot schema／商業規則重播。83 個正式金融未知、三個 TTM null、同模型期限制與完整 baseline 的原缺口仍在。
