# 已存事件節點範圍驗證

在獨立暫存副本重現：把已存事件的 affected_nodes 改為不存在的節點，同步 snapshot.event 並重算 hash 後，新增事件路徑拒絕，但 canonical load 仍接受。Hash 一致不能取代事件範圍的語意驗證。

新事件與已存事件共用範圍檢查：起始節點必須在資產登記中，圖譜端點必須有效，每筆更新的 asset 必須可由起始節點傳播到達。已存事件還要求 propagated_nodes 完整且無重複；缺少、型別錯誤、遺漏或多列都拒絕。節點順序不影響集合判定。原 affectedNodes 匯出與傳播演算法保留；可到達不表示已驗證經濟傳輸或採用完成。

已存事件使用各自完整快照內的資產登記及圖譜，先套用既有登記 schema、唯一 ID 與端點檢查，再核對範圍。日後目前圖譜加入依賴，不會要求歷史事件冒認當時尚未存在的傳播節點。這是內部一致性驗證，不是外部簽章認證、來源內文查證或全部已存商業規則的重播。

新增 21 項回歸覆蓋兩工作區、不存在節點、已知／未知的跨資產更新、六種無效傳播清單、合法下游與多起始節點、目前圖譜改版後的歷史範圍、無效快照登記、失敗套用不寫入、API 400 與 journal bytes 保留、真實金融／論點／全部歷史 hash。與既存事件及血緣測試合計 63 項通過；修正前兩項不存在節點回歸確實失敗。實際全套結果見[驗證紀錄](validation.md)。

沒有修改 spec／來源／觀察／假設／公式／圖譜資料、既有快照或介面。正式資料仍有 83 個金融未知、三個正式 TTM null；六份快照仍同模型期間。SECZ 登記／現況股本／法律名稱／TTM 與同步估值、個人管道及 UNI 全期間捕獲仍待查證，父 baseline 未完成。
